### 門檻寫咗入 schema

`Interpretation` 個 `superRefine` 直接執行 §16 / §17：

- 單一去重群 → 唔准出方向評級（§14）
- 進／逆要三群，盛／險要四群（§16.2、§16.3）
- `low` / `undetermined` 唔准出評級；`medium` 上限 ±2（§17）
- 盛／險要 `high` ＋ `manual_review_passed`（§16.3）
- 年度結論要本命／大限／流年三層都 `passed`（§13）
- `grade: null` 唔准有 `title` / `body`，只可以出 `reader_note`（§16.6）
- 「平」要 `input_quality: complete` —— 缺資料應該係 `null`（§16.5）
- `fixture://` 唔准 `approved`

### 門檻以外：內容層自己嘅六道閘

呢六道唔喺規範度，係寫嘅時候撞板撞返嚟：

| 閘 | 喺邊 | 攔乜 |
|---|---|---|
| 引文核對 | `lexicon.ts` | 每個 `quote` 要喺語料庫原文**逐字**搵得返（簡繁 normalise 之後）。抄錯一個字就 parse 唔到 |
| cell 級來源 | `baseblock.ts` | 一條交集結論至少要一個真係講緊「呢粒星喺呢個宮」嘅原文。星級加宮級唔算 |
| 句內重複 | `modifier.ts` | 同一句入面**七**字以上嘅重複片段 → fail。error message 寫住「湊字數就係巴納姆嘅入口」 |
| 錨詞 | `frame.ts` | 收束句最少要中一個本宮錨詞。一句「邊一宮都啱」嘅留白句，就係一句「邊個人都啱」嘅話 |
| 人稱 | `baseblock.ts` | 讀者一律「你」，星一律「它」，第三者用具體稱呼。**冇「他」呢個代名詞** |
| 追溯率 | `gate.ts` | 改完一段之後，每個字要喺原塊搵得返（LCS ≥ 0.9）。刪得、接得、換人稱得，**加唔得** |

頭三道係犯咗錯之後補嘅。第四道係 C7 寫嗰陣即刻捉到一句 ——
`close.官祿.4` 原本寫「如果沒有人看見，你手上這件事你還做不做」，
搬去邊一宮都讀得通，所以佢唔係講官祿，佢係講人。

第三道個窗由八字收到七字，係因為 **C8b 砌樣章嗰陣見到一句漏網嘅**：
「什麼都停在入門」啱啱好七個字。收窄之後一次過捉到十一條同樣寫法嘅修飾語。
個窗唔係因為七係一個好數字，係因為**八漏咗一個真個案，而漏咗一次就會漏第二次**。

第五道亦都係 C9 掃出嚟：章框（60 句）同 L3（70 條）全部用「你」，
但有十四條基塊用「他」講讀者 —— 同一章入面兩種人稱。
讀者唔會覺得係兩個層，佢會覺得係寫得唔小心。

## 三、規範要求咗，但係我哋未有嘅嘢

呢一節係 C1 做完之後最重要嘅發現。**唔好當佢係 TODO 清單，佢係三個真缺口。**

### 缺口一：冇規則庫，冇 school_profile —— ✅ 2026-09 機制做咗（B13 / C2），內容仲係薄

§10 要求每條規則有 `rule_id`、版本、適用流派、所需輸入、觸發條件、排除條件、
容許象義、禁止延伸、可支持主題、依賴關係、審核狀態；
§17 要求每個結論物件填 `school_profile_id` 同 `rule_registry_version`，唔准用 `latest`。

而家兩樣都有：

| | |
|---|---|
| `school_profile_id` | `zhongzhou-v1@…`（B13，`packages/ziwei/src/school-profile.ts`） |
| `rule_registry_version` | `r1@…`（C2，`packages/content/src/registry.ts`） |

#### 觸發條件係資料，唔係程式

一條規則嘅觸發條件係一舊 JSON，由 `src/condition.ts` 直接對住 `Chart` 行：

```json
{ "hua": "忌", "in": { "name": "官祿", "layer": "annual" }, "layer": "annual" }
```

咁做嘅理由唔止「可以出版本」。最緊要嗰個係：
**evaluator 唔止回 true／false，佢回埋 binding**（邊個宮、邊粒星、邊個化、邊一層）。
冇 binding 就砌唔到 §17 要求嘅 `evidence[]` —— 一條答唔出「因為邊一格」嘅規則，
喺呢個系統入面係冇用嘅。

所以條件語言入面**冇 eval、冇 `new Function`、冇字串運算式**。
唔夠用就加原子，唔准開後門。

#### 三道閘

| 閘 | 攔咩 |
|---|---|
| 流派 | 規則聲明適用流派，同 `school_profile_id` 唔夾就 `blocked` |
| 審核 | `draft` / `needs_review` / `rejected` 一律唔出 evidence，連行都唔行 |
| 輸入 | 所需輸入唔齊 → `not_applicable`，**唔係 `unmatched`** |

第三道最易做錯，亦都係最重要。「冇流年資料所以查唔到」同「查過，冇」係兩件事；
一混埋就會由缺資料推出「未見反證」，而 §14 明文寫住「未見支持不等於已有反證」。
呢個分別喺型別度就守住：`EvalResult` 有三個狀態，唔係兩個。
`not` 包住一個 `not_applicable` 仍然係 `not_applicable` —— 否定一個「唔知」唔會變成「真」。

#### 來源分兩種，唔好撈亂

呢個係 C2 做落去先至清楚嘅分別，而佢決定咗邊條規則審核得到：

| | 出處 | 例 |
|---|---|---|
| **(a) 我哋自己嘅規矩** | `voice-spec.md` 本身 | 「化忌容許講牽制／反覆」—— 呢個係我哋准講邊啲詞，唔係對斗數嘅主張 |
| **(b) 對斗數嘅主張** | 要書，要頁碼 | 「殺破狼代表乜」、「廟旺表點填」 |

而家 `approved` 嘅 12 條全部係 (a) 或者純幾何。
所有 (b) 類（格局、星曜象義）一律 `needs_review`、`sources: []`，
行到嗰度會出 `blocked`。

**呢個唔係保守，係 §10 最後嗰句：「缺少已審核規則時，不得即席創作星曜含義。」**
呢句寫落 prompt 度冇用 —— 一個生成模型永遠有嘢好講。所以做成機制。

#### 而家真係寫到幾多？

C2 交嗰陣：七個主題入面三個零規則，一副真盤得**一個去重群**命中，
正確輸出係 `grade: null`。呢個係好消息 —— 佢係規則庫太薄照出嚟，唔係我哋扮有嘢講。

C3 → C4 → C5 → C6 → C7 之後，同一副盤：

| | C2 | C4 | C5 | C6 | C7 |
|---|---|---|---|---|---|
| 規則庫 | 15 | 87 | 183 | 295 | **352** |
| career 群數 | 0 | 0 | 1 | 4 | **5** |
| career 上限 | 平／null | 平／null | 平／null | 順／慎 | **進／逆** |
| 七個主題過到 §14 | 0 個 | 3 個 | 4 個 | 6 個 | **7 個** |

**呢張表要小心讀。** 「七個主題全部過到 §14」唔等於「而家乜都寫得到」：
§14 只係最低門檻（兩個群），上面仲有 §16 嘅階梯。
同一副盤入面 `home` 就卡喺順／慎 —— 而且卡住嘅原因唔係規則庫唔夠：
田宅嗰兩條三方四正規則寫咗、審核咗、跑咗，**只係冇命中**。呢副盤嘅田宅真係靜。

「我哋寫唔到」同「呢副盤冇嘢好講」係兩件事，第二樣係正確答案。
`test/integration.test.ts` 每次門檻鬆一格就要補返一條問「乜嘢仲係寫唔到」——
一個每個主題都答得出嘢嘅系統，就係一個冇門檻嘅系統。

#### C7 帶出嘅兩個決定

**一、九個格局永久拒絕，但唔准刪。**

《全書》太微賦有一批凶格，佢哋被記錄低嘅**唯一**象義就係 §19 硬閘禁止嘅嘢：
路上埋屍、水中作塚、殺居絕地（天年夭似顏回）、鈴羊合命（須當刑戮）、
七殺臨身命（必定死亡）、枷杻難逃、離鄉遭配、沿途乞食、終身鼠竊。

呢啲唔係「證據唔夠所以暫時唔寫」，所以佢哋唔係 `needs_review`，係 `rejected`：

| | `needs_review` | `rejected` |
|---|---|---|
| 意思 | 而家證據唔夠 | 任何證據都解鎖唔到 |
| 補多一本書會點 | 可能變 approved | **仍然唔會出** |
| 觸發條件 | 留低 | **一樣要留低** |

最後嗰行先係重點。刪咗個 entry，下一個人睇返太微賦就會「重新發現」呢個格局，
然後當成一件新嘢寫出嚟。**留低一個已經判過嘅決定，係唯一阻止佢被重新發現嘅方法。**

**二、章框係全本書唯一冇來源要求嘅一層 —— 代價係佢一個字都唔准講命理。**

L5 章框（開場導語、過場句、收束留白句）冇 `sources`。唔係因為佢唔緊要，
而係因為**佢冇對斗數作出任何主張**：「這一章讀財帛宮，不談金額」講緊我哋
自己嘅編輯規矩；「你手上的錢，有多少是等回來的」係一條問題，唔係一個斷言。

但呢個豁免會變成後門，所以要有代價 —— `Frame` schema 自己擋住星名、化別、
廟旺、煞曜。一句「天梁在此宜守」放喺留白句度，就係一條冇出處嘅象義斷言，
而且係喺全章最後、讀者最記得嗰個位置。

同一個道理落埋喺內容系統 §7 嗰道 AI 收尾閘。規範寫住 AI 准「生成過場句」——
但「生成」係一個驗唔到嘅字眼：事後判一句 AI 寫嘅嘢係咪過場句，冇得驗。
所以 repo 呢邊改成：**AI 唔准作過場句，只可以由 bank 揀。**
`transitionWhitelist()` 直接由過場句 bank 出，兩者同一份資料，唔會走音。

**剩低嘅係內容，唔係機制。** C3（L0 詞條）同 C4／C5（L1 基塊）每寫一條順手
declare 一條規則，規則庫就會厚返 —— 唔係另外寫三百條。

### 缺口二：引擎追唔上規範 —— ✅ 2026-09 關咗（工單 B14 / B15）

§10 必要欄位入面，引擎而家嘅狀況：

| 欄位 | 狀況 |
|---|---|
| 本命、大限、生年四化、廟旺 | ✅ 有 |
| 三方四正、空宮借星 | ✅ B14 做咗 |
| 流年及流年四化 | ✅ B15 做咗 |
| 大限四化 | ✅ B15 做咗（大限命宮嘅本命宮干引動） |
| 限流疊宮 | ✅ B15 做咗（三層宮名並排） |
| 自化、飛化、向心／離心 | ⛔ **三合派唔用 —— 係選擇，唔係缺陷** |
| 流曜、小限、流月流日 | ❌ 未做 |

**§16 嘅年度門檻而家滿足得到。** 流年群同大限核心支持兩樣都出得到，
所以內容系統 §9 字數表嗰 1,500 字流年章有引擎撐得住喇。

⚠ **但有一個例外要記住：未起運嗰幾年冇大限層。**
水二局要虛歲 2、火六局要虛歲 6 先起運，之前嗰幾年 `annual().decadal` 係 `null`。
嗰啲年份嘅年度章**照樣寫唔到** —— §16 要大限核心支持。
呢個唔係 bug，係事實；推理器（C8）要識得喺呢度出 `grade: null` 而唔係硬寫。

剩低嘅引擎缺口只有流曜、小限、流月流日，三樣都唔喺 §16 年度門檻嘅必要路徑上。
**而家攔住年度章嘅係內容線（C2 規則庫、C8 推理器），唔再係引擎。**

### 缺口三：內容架構同規範之間差一層

| | 內容系統 v0.1 | voice-spec v1.0 |
|---|---|---|
| 產出 | 168 條靜態基塊，按命盤揀塊砌 | 每個結論一個 `interpretation` 物件 |

**兩者唔係唔兼容**，但係中間缺咗一層：

塊本身唔使重寫（每塊兩個來源嗰條規矩仍然啱），
但 **C8 由「揀塊器」變成「推理器 ＋ 揀塊器」** —— 呢個唔止四日。

### 缺口四：⚠ 方向 —— C8 照出嚟嘅新缺口

§16 成套機制建立喺「至少兩群**同向**證據」之上，所以證據要有方向。
但 §14 同時明文禁止「祿必富、權必升、科必考上、忌必凶」。

兩句加埋嘅意思唔係「方向唔存在」，係**方向係一個主張，要有根據**。
所以 C8 做咗一個決定：

> **方向唔係一個人手標嘅欄位，係由規則自己已登記嘅 `allowed_xiang` 查返出嚟。**

分別喺邊？標欄位嘅講法係「我覺得呢條算順」；查象義嘅講法係
「呢條規則登記咗嘅詞入面，有冇一個係講方向嘅」。後者答得出點解。
`src/rules/valence.json` 就係嗰個詞庫，而且**規則庫入面每一個象義詞都一定要分類過**——
新增一個未分類嘅詞會 build fail，所以冇人可以靜靜雞加個有方向嘅詞令一個主題突然夠票。

後果係一個要記住嘅數：

| | |
|---|---|
| 已審核規則 | 347 |
| 講得出方向 | **64**（順 39／阻 25） |
| 基塊派生（`base.*`） | 168 條，**一條都冇方向** |

**基塊冇方向唔係 bug，係 C4 個設計。** C4 寫基塊嗰陣就決定咗
「基塊只寫交集張力，唔寫吉凶」——「紫微坐命」嘅登記象義係
主導／承擔／標準／體面，四個都唔係方向。而基塊係核心票嘅大部分來源。

同一件事喺四化度更清楚：

| 化 | 登記象義 | 方向 |
|---|---|---|
| 祿 | 資源／順流／得以展開 | 順 |
| 忌 | 牽制／反覆／需要承擔 | 阻力 |
| 權 | 推動／**承擔**／決定權 | **冇** —— 規範自己把兩個相反方向寫喺同一格 |
| 科 | 呈現／秩序／名目 | **冇** —— 根本唔係一個方向 |

所以 C7 嗰張「六個主題上到進／逆」嘅表要改口徑讀：
`gradeCeiling()` 出嘅係**結構上限**（數群、數角色、數層），
佢唔問「呢啲群指緊邊個方向」。加返方向之後，同一副樣本盤：

| self | career | finance | relationship | home | social | load |
|---|---|---|---|---|---|---|
| null 交錯 | null 觀察 | **+1 順** | null 觀察 | null 觀察 | 0 平 | null（§19 硬閘） |

**七個主題得一個出到方向。** 呢個係缺口，唔係毛病 ——
補法唔係放鬆門檻，係畀基塊一個**有出處嘅方向象義**，而嗰個係內容工作，唔係開關。

**落實喺兩個地方，兩個都係機制唔係規矩：**

一、`BaseBlock.direction` 三樣缺一不可 —— 方向詞（要喺 `valence.json` 登記過而且方向夾）、
**cell 級**來源、引文要喺原文逐字搵得返。「紫微屬土」（star 級）撐唔起
「紫微坐命係順」。搵唔到就冇方向，冇得靠感覺補。

二、`directionalBlocks()` 而家回 **0**，有測試守住。
佢同 `singleBookEntries()` 係同一種東西：**一個唔會自己郁、要靠做嘢先加得到嘅計數器**。

而且方向落到規則度**冇特事特辦嘅路徑** —— 佢只係多一個 `allowed_xiang` 詞。
推理器唔識「基塊有方向」呢回事，佢只識查象義。所以想開後門，就一定要經同一道門。

#### 甲嘅另一半：觀察章唔止一種

`grade: null` 由例外變成常態，所以佢要分得出係邊一種 ——
五種要寫成五個唔同嘅樣，而 C8 出嘅 `trace.kind` 就係嗰個分類：

| kind | 意思 | 讀者應該讀到 |
|---|---|---|
| `flat` | 盤點完成，真係冇方向 | 呢一格靜 |
| `conflicted` | 兩邊都有，講唔埋一個方向 | 兩頭都有，埋唔到一個講法 |
| `observation` | 有訊號但唔夠票 | 見到一樣嘢，未夠講 |
| `missing` | 嗰一層根本冇資料 | 呢一層冇嘢查得到 |
| `hard_gate` | §19 —— 有幾多證據都唔講 | **呢一章唔出方向，唔係因為證據** |

⚠ 最後嗰種最緊要。一個讀者見到疾厄章冇方向，好自然會讀成「即係冇事」，
但佢嘅意思係「呢個位我哋唔講」—— 兩句喺紙上面一樣，喺讀者心入面差好遠。
所以仲有一個 `trace.preGateGrade`：「本來都係 0」同「本來係 −2，我哋特登唔講」，
C8b 寫出嚟唔可以一樣輕。

## 四、一個編輯建議

§13 嘅權重表寫住「基礎權重 3 / 結構驗證權重 2 / 修正權重 1」，
然後下面即刻要警告「**禁止直接相加**」、「三項權重 1 唔等於一項核心權重 3」。

既然唔准相加，啲數字就冇運算意義，淨係製造咗一個要另外去禁止嘅誤解。
而 §16 嘅實際機制係**數去重群、分角色**，唔係加權重。

**建議下一版拆走 3 / 2 / 1，直接用角色名：核心 / 結構驗證 / 修正 / 關聯。**
`packages/content` 嘅 `EvidenceRole` 已經係咁寫（`core` / `structural` /
`modifier` / `link` / `none`），因為寫程式嗰陣揀唔到用數字 —— 一寫落去就想加。
