## 一、定咗嘅決定

### 1. 舊盤唔自動重算（R-008）

一本書排出嚟嗰一刻，`engine_version` · `school_profile_id` ·
`content_version` 三個值鎖死。引擎升級，舊書一個字都唔變。

**理由**：佢哋（fatemaster.ai）係工具，工具應該永遠最新；
我哋係命書，**你收到嗰本應該一直係嗰本**。

配套三樣，缺一就變成「賴死唔改」：

- 版權頁列出三個版本號 ＋ 一句「日後算法或文字改版，這本書不會自動跟著改」
- `/account` 並列新舊差異，由用戶揀
- **重排係造一本新書，唔係改舊嗰本** —— 舊嗰本要仲喺度

⚠ R-008 **唔入** `SCHOOL_PROFILE.rules.registry`：佢改變唔到任何一格，
而一個唔影響輸出嘅規則唔應該令輸出嘅指紋變。

### 2. 收費：一次過買成本書 · USD · 價錢未定

| | |
|---|---|
| 賣乜 | 一張票開晒全部深度章 |
| 貨幣 | USD |
| 價錢 | **未定**。而家 `US$1.00`，`PRICE.placeholder: true` 標住佢係假 |

**理由**：架構 §6 分咗六組，但六組入面**得三組生成到**（四化／大限／流年
等 C11）；而且 `chapter_body()` 由 G1 起就係查「呢本書有冇票」，
揀一次過買，**DB 一個字都唔使改**。

逐組賣冇否決永遠 —— `entitlements.product` 同 `unique (reader, book, product)`
都仲喺度。改嘅日子要改 `chapter_body()` ＋ `chapters` 加「屬邊組」一欄。

### 3. 票由 webhook 發，唔由返嚟嗰版頁發

一個人撳完畀錢之後返唔返到我哋版頁，**我哋控制唔到**（熄 tab、斷線、
撳返上一頁）。票由嗰版頁發，就係收咗錢冇畀嘢。

`/pay?done=1` 淨係問一句 `has_entitlement()`，照實講三句之一：
票到咗／畀咗錢票未到／冇畀錢。

### 4. 未認領硬閘三層，而第二層先係真嗰道

| 層 | 擋嗰陣 |
|---|---|
| `/pay` 版面 | 佢仲未撳 |
| **`checkoutAction`（server action）** | **佢撳咗，但未去到 Stripe** |
| DB trigger | ⚠ 佢已經畀咗錢 |

server action 係一個公開 HTTP endpoint：匿名讀者用 `curl` 直接 POST
係入得到 checkout 嘅，除非嗰度自己查。

### 5. 付款紀錄同人分家

`payment_records`：**冇 `reader_id`、冇 `book_id`、冇 FK**。

**理由**：`entitlements` 係 cascade，一撳刪除「呢筆錢幾時收過」同張票
一齊消失。噉樣唔係保護私隱，係做唔到會計 —— 而做唔到會計嘅系統，
遲早會被一句「不過我哋要留返紀錄」推翻成標記刪除。

分咗家之後，人刪咗嗰行嘢仲喺度，但**佢唔再係關於任何人嘅資料**。

### 6. 真刪係 `delete`，唔係 `deleted_at`

標記刪除係最容易滑落去嗰個做法 —— 佢一樣令人見唔到自己啲嘢，
而且「萬一佢想恢復呢」聽落好體貼。但**一個標記咗刪除嘅生辰，
仲係一個我哋揸住嘅生辰**。

兩步：`delete_reader()`（資料，cascade）→ `auth.admin.deleteUser()`（email）。
第二步要 service_role 而且會仆街，所以**三個結果三句唔同嘅嘢**，
唔准報「已經全部刪除」。

刪除要**打字**先做得到 —— 一個「你確定嗎？」對話框，喺一個已經撳咗一下
嘅人面前，基本上係一個要撳多一下嘅掣。

### 7. 匯出唔係一道後門

`export_reader()` 係 **security invoker**：未買嘅章 `body` 係 `null`，
而且檔案自己寫明點解。匯出檔個名冇生辰冇姓名。

### 8. Analytics：閘喺型別，唔喺 code review

事件表寫死咗每個事件准帶嘅欄同每個欄准係邊幾個值。表入面冇一個 `string`。

- 欄名擋第一層
- **值擋第二層，而第二層先係真嘅**：欄名可以改成 `q`，但一個 enum
  塞唔入 `1996-06-16`

⚠ **「唔記值」唔止係「唔記生日」**：五行局＋命宮＋性別一齊收窄緊同一個
出生時刻，所以盤面值同生辰同一級。讀者／書 id 都唔准入 —— 假名唔係匿名。

而家**一個 provider 都未接**，`track()` 乜都唔做。

### 9. 一套卷首、一個台、一個天頭（UX1）

「唔夠連貫」量得到：`/shelf` `/cast` `/account` 天頭 40px、版心左邊 124px；
其餘四版 104px / 319px。即係**由書齋撳入一本書，標題向右跳 195px**。

而 `104 : 64 = 8 : 5` 係視覺系統 §5 唯一一條佢自己話「淨係呢一條，
成版就唔似普通網站」嘅規則。

- `Juanshou` = 全站唯一頁頭：返回／夜讀 · 章名／細 nav · 界欄
- `.tai`（1080）**唔係新尺寸**，係將已經有嗰個用法寫成一個名；
  台入面再用 `.banxin` 收返版心，所以闊嘅嘢攤得開而字永遠喺同一個位起
- 「書架」統一做「書齋」；命書同章加返細 nav；夜讀擴到讀書嗰幾版

### 10. 用 Stripe hosted Checkout

第二個理由先係重點：**唔使喺自己版度載 Stripe 嘅 JS**，
即係第三方名單唔會多一個 host。而「揀咗唔載」同「真係冇載」之間
差一個量度，所以 `check-privacy` 連 `/pay` 一齊掃。

## 二、推翻咗嘅方案

| 諗過 | 點解唔要 |
|---|---|
| **逐組賣深度章** | 六組得三組生成到，即係賣緊三組空章；而且 DB 要改 |
| **用 `entitlements` 留會計紀錄** | 佢係 cascade，一刪人就清走 —— 留唔到 |
| **先刪 auth 再靠 cascade 清** | admin API 一仆街就係**一樣嘢都冇刪而個人以為刪咗**。而家敏感嗰啲行先 |
| **成功頁「請稍候」＋自動 refresh** | 係喺度扮緊「你等一等就會好」，而我哋唔知 |
| **似真嘅假價錢（`US$29`）** | 會喺截圖同 demo 入面扮到自己係真，然後冇人記得佢係假。一蚊唔會 |
| **匯出用 service_role 撈晒** | 會連未買嘅深度章正文一齊交出去 —— paywall 多咗一條叫「匯出」嘅繞路 |
| **用 localStorage 記「裁開咗未」** | 清 cookie 或者換機就會再裂一次，即係「一生」其實係「呢個瀏覽器呢一次」。改用 `chapters.cut_at` |
| **逐版自己寫頁頭** | 四款頁頭，每開一版新頁就要由零再揀一次，只會越揀越散 |
| **`recastHref` 指去一個編輯畫面** | 重排係造新書，唔係改舊嗰本 |
