# 競品拆解：destiny-vector.com（命運矢量，2026-10-14）

只讀咗公開頁面同前端程式碼，**未提交過表單、未生成過 AI 解讀**，所以以下講嘅 AI 輸出係由 prompt 推斷，未見過真實文字。

## 一句講晒

排盤同 starnum 一樣用開源 `iztro` 喺瀏覽器計；**解讀全部係即時叫 LLM 生成**——程式碼入面叫嘅係字節跳動嘅**豆包（Doubao）**，prompt 喺前端砌好再經佢哋自己個 API proxy 轉發。目前睇落全部免費，冇見到收費入口。

## 1. 流程同架構

- **首頁表單**：姓名、性別、出生日期、**準確出生時間**、出生地（輸入城市自動搜尋，用自建 Nominatim／OpenStreetMap proxy `map.destiny-vector.com` 轉經緯度，再用 `tz-lookup` 搵歷史時區）。另有「雙人婚戀解讀」（`relationship.html`）。
- **真太陽時**：`destiny-engine.js` 自己計——經度 × 4 分鐘減時區偏移，加均時差近似公式（9.87 sin2B − 7.53 cos B − 1.5 sin B），仲會偵測夏令時間。分「早子／晚子」。
- **排盤**：`iztro`（自己 host 一份）＋ Temporal polyfill。
- **AI**：`ai-service.min.js` lazy-load。每次請求：
  1. Cloudflare **Turnstile**（隱形人機驗證）攞 token；
  2. `POST {api}/web/{kind}-session` 換一個 report token；
  3. `POST {api}/web/{chart|insight|chart-view|relationship}-infer`，body 係 OpenAI 格式嘅 `messages` + `temperature` + `stream:true` + `thinking:{type:"disabled"}`（豆包 API 嘅參數）。
  4. 串流返嚟逐段畫（每 48ms 更新一次），結果 cache 喺瀏覽器。
- 錯誤會重試 3 次（408/429/5xx）；`finish_reason === "length"` 會報「輸出被截斷」。
- **私隱頁同程式碼唔夾**：私隱頁寫 AI 引擎「如 OpenAI/Anthropic」，實際 code 叫 `DOUBAO_API_URL`、log 寫 "Doubao API Error"。私隱頁又提到「支付處理」同「判斷您是否已支付某次報告」嘅 cookie，但前端搵唔到任何付款代碼——似係之前有收費、而家拎走咗，或者準備緊。

## 2. 解讀嘅結構（由 prompt 睇）

**互動式、按需生成**，唔係一本書：撳邊度先生成邊度。

| 功能 | 輸出 |
|---|---|
| 本命 | 總論 |
| 單宮 | JSON：overview、stars_analysis、strengths ×3、challenges ×2、advice、**score 1–100** |
| 大限 | JSON：summary（score + 4–8 字 headline）、career／wealth／love／health 各自 **trend up/down/stable** + 50–100 字 + 建議、turning_points（關鍵年齡） |
| 流年 | 同上，加化忌沖宮、大限疊流年 |
| **完整報告 8 章** | 命盤總論、性格天賦、事業財運、情感家庭、身心健康、人際協作、十二宮圖、五年指引；逐章串流，可下載 TXT |
| 雙人 | 婚戀合盤 |

即係：**分數 + 趨勢箭咀 + 一句 headline** 俾人一眼睇到（同 starnum 一樣係「一眼答案」路線），再展開文字。

## 3. 佢哋 prompt 寫得幾好——同我哋原則好接近

完整報告嘅 system prompt 要求：
- 「先看懂『這對我意味著什麼』，再自然明白『為什麼會這樣看』」——即係結論先行。
- 術語第一次出現時句內極短白話解釋。
- 每章開頭 60–100 字「本章主線」。
- **禁止模板句**（「運勢不錯」「注意溝通」「貴人相助」「宜守不宜攻」）；相鄰段落唔好重複起句。
- 每個核心判斷至少落喺一項可核對嘅盤面事實；最重要嘅 2–3 個判斷用唔同證據組合。
- 正面同挑戰要成對出現；用條件句；唔虛構事件；健康唔推斷疾病。
- 證據分級：**direct／indirect／insufficient**——證據不足要明講「冇強直接訊號」，唔准補造月份或宮位。
- 加粗每章 4–8 處，唔用表格。

呢套差唔多就係我哋 de-template、plain reader copy、減機械感幾輪嘅規則，佢用 prompt 寫低咗。

**但有幾個根本限制：**
1. **冇派別**：prompt 叫 AI「精通三合、飛星、河洛、欽天四化等各流派」——即係冇立場，AI 自由混用。iztro 預設嘅四化表（庚干太陰化科）亦冇處理。
2. **冇出處**：AI 只能引「盤面事實」，引唔到書、頁、段。同我哋「每句追到王亭之書」比，佢冇得驗證。
3. **每次唔同**：temperature 0.7 串流，同一個盤再生成會講唔同嘢；分數 1–100 由 LLM 拍出嚟，冇規則。
4. **成本跟用量走**：每個讀者每次撳都係 API 費用，所以要 Turnstile 擋機械人。我哋係預先寫好嘅內容，邊際成本近零。
5. **prompt 全部喺前端**：任何人都睇到佢成套 prompt（我哋而家就係咁睇到）。

## 4. 其他

- 5 種語言（繁簡英日韓），英文市場似乎係重點（sitemap 英文版最新、keywords 寫「Zi Wei Dou Shu vs Vedic astrology」）。
- 首頁設計：深色星空、three.js 動畫、範例命盤用飛化箭咀示範「化忌從財帛宮飛去遷移宮」——**用一個虛構例子示範解讀長咩樣**，幾有效。
- 定位口號：「不是預言，而是導航」「別只問會不會發財，要問財從何處來」。
- 「規則排盤，而非 AI 猜測」——佢哋自己都知要講清楚盤係規則計、AI 只負責講。
- 分析：Cloudflare Web Analytics、GA4。冇廣告。

## 5. 對星敘嘅啟示

**可以學：**
1. **首頁示範一段解讀**：用虛構盤示範「財帛宮化忌牽動遷移宮 → 去外地工作收入可能俾租金食晒 → 建議：跨城費用單列預算」。一段就講清楚我哋嘅解讀係咩樣。我哋可以用 sample book 一段（連出處）做同樣嘅示範。
2. **證據分級嘅講法**：「呢方面盤上冇強訊號，以下以本命傾向為主」——坦白講冇嘢講，好過硬寫。可以考慮加入我哋命書寫法。
3. **主題入口**（財富、事業、感情、健康四個「矢量」）——再次印證 starnum 拆解 §9 第 1 項「你想知咩」入口。
4. **「規則排盤，AI／文字只負責講」嘅分工講法**，方法頁用得着。

**我哋嘅優勢（可以喺首頁講）：**
- 有派別（中州派）、有出處（書／頁）、同一個盤每次讀都一樣。
- AI 站最弱嘅正正係「點解你咁講？」——我哋答得到。

**唔好學：**
- LLM 拍出嚟嘅分數同 up/down 箭咀。
- 私隱頁寫一套、code 做另一套。

## 6. 實測（假生日 1990-05-15 10:00 男 台北，2026-10-14）

- 地點輸入「Taipei」會出「臺北市, 臺灣」建議；頂部顯示「真太陽時 10:10」，同 starnum 一樣。
- **命盤同 starnum 完全一樣**（命宮子破軍廟、福德寅紫微天府、田宅卯太陰陷……），即係同樣用 iztro 預設，庚干化科放太陰，唔係中州派嘅天府。
- 一提交就彈 Cloudflare Turnstile。用戶親手撳咗「Verify you are human」，但所有 AI 請求（`analyzeNatal`、`analyzeDecade`）都回 **Turnstile verification failed (600010)**，畫面顯示「分析失敗，請稍後重試」。重試一次結果一樣。600010 通常係 Cloudflare 判斷瀏覽器係自動化工具，所以喺 Claude 嘅瀏覽器入面攞唔到 AI 輸出；我冇嘗試繞過。
- 結論：**真實 AI 文字未見到**。要對比，需要用戶喺自己嘅瀏覽器跑一次，貼返本命解讀同一章完整報告（或者用佢個「下載 TXT」）。
