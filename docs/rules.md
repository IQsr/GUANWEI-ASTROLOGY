| | |
|---|---|
| **我採用** | `lateZiHour: 'next-day'` —— 23:00 之後算翌日嘅子時 |

| **受影響嘅人** | 每日一小時，約 **4%** 用戶 |

## R-004　日期基準：出生地當地日 vs 中國時間

| | |
|---|---|
| **我採用** | 出生地當地日（經真太陽時校正之後嗰一日） |
| **其他做法** | 一律換算成中國時間再查農曆 |
| **影響** | 農曆日 → 安紫微。海外出生者可能差成個月 |
| **受影響嘅人** | 所有非東八區出生嘅人，喺當地日同中國日唔同嘅時段 |
| **核實狀態** | 暫定 |

**理由**

呢條係寫 B1 嗰陣先浮出嚟嘅第四個分歧點，原本三條入面冇。

農曆本身係按中國時間（1929 年起 UTC+8）定義嘅曆。咁一個喺倫敦早上八點
出生嘅人，佢嘅農曆日應該係倫敦嗰日，定係當時中國已經係下午四點嗰日？
兩者有時係同一日，有時唔係。

採用**當地日**：一個人嘅生日係佢出生嗰度嗰一日。加上我哋已經做真太陽時
校正 —— 校正本身就係將時間拉返去出生地嘅太陽，用中國日就自相矛盾。
現代排盤軟件多數亦都係咁做。

## R-005　節界：精確交節時刻 vs 日粒度

| | |
|---|---|
| **我採用** | 精確交節時刻 —— 立春 16:17 交節，當日 12:00 出世仍然算上一個月 |
| **其他做法** | 日粒度 —— 節氣當日一律算新月（cnlunar 等較簡單嘅實作用呢個） |
| **影響** | 月柱月支。**三合派斗數核心用唔到月柱**，所以實際影響好細 |
| **受影響嘅人** | 每年十二日入面、交節時刻之前出世嗰批 |
| **核實狀態** | 暫定 |

**理由**

節氣係天文時刻，唔係一日。專業排盤用精確時刻；日粒度係簡化。
既然我哋個表已經有分鐘級數據，冇理由降級。

影響細嘅原因：安命宮用**農曆月**，唔係節氣月。月柱喺三合派入面基本上用唔著。
如果將來要試四化派（重視月柱），呢條要再諗，而且可以加 `jieBoundary` 開關。

**順帶一條唔係分歧、但好容易寫錯嘅嘢：月干要用「立春年」嘅年干起五虎遁，
唔係用年柱嘅年干。** R-001 揀咗正月初一做年界，所以喺正月初一同立春之間
兩者會唔同。月柱本身係節氣曆嘅產物，一定要跟立春年 —— 混用會令 1984-02-02
呢類日期嘅月柱錯成 丁丑（正解 乙丑）。呢個 bug 喺 B4 真係出現過。

**來源**

- 通行八字實務用精確交節時刻。
- 對照庫 cnlunar 用日粒度 —— 已記錄，測試 oracle 排除節氣當日嘅個案。

## R-006　閏月出生點定宮位

| | |
|---|---|
| **我採用** | 上半月（初一至十五）算本月，下半月（十六起）算下個月 |
| **其他做法** | 一律算本月；一律算下個月 |
| **影響** | 安命宮、安身宮 —— 即係成個盤 |
| **受影響嘅人** | 閏月出生者。約每三年一個閏月，即係約 2–3% 人 |
| **核實狀態** | 暫定（有旁證） |

**理由**

安命宮由「寅宮起正月，順數至生月」開始，所以「生月」係邊個月一定要有答案。
閏月冇自己嘅月號，三家做法都有人用。

採用上半月／下半月分界，理由係佢係三合派較通行嘅講法，
而且同閏月嘅本義（補一個月嘅時差）一致：前半仍屬舊月，後半已屬新月。

**旁證**：兩個實作用同一個規則。

- 開源 iztro 嘅 `fixLeap: true`：206 個對照個案（含六個閏月個案）全對
- 商業 文墨天機 pro 2.5.9：四張閏月盤（B03–B06）全對，包括上半月／下半月
  分界兩邊各兩張 ——

  | | 農曆 | 文墨命宮 | 本引擎 |
  |---|---|---|---|
  | B03 | 庚午年閏五月**初一** | 子 | 子 ✓ |
  | B04 | 庚午年閏五月**十六** | 丑 | 丑 ✓ |
  | B05 | 癸酉年閏三月**初一** | 戌 | 戌 ✓ |
  | B06 | 癸酉年閏三月**十六** | 亥 | 亥 ✓ |

  （B03 / B04 要強制 UTC+8 先對得上 —— 原因係夏令時，見 R-007，唔關閏月事。）

兩個都唔算文本出處，但初一同十六啱啱好差一個宮，兩邊都一樣，
呢個做法有實作基礎。

**實作**：`packages/ziwei/src/chart/palaces.ts` 嘅 `monthForPalace()`。

## R-007　歷史夏令時

| | |
|---|---|
| **我採用** | 認。跟 IANA 時區資料庫，鐘錶時間先還原做標準時，再做真太陽時校正 |
| **其他做法** | 唔認 —— 當東八區永遠 UTC+8（文墨天機 pro 2.5.9 係咁） |
| **影響** | 時辰 → 命宮、身宮、安星；嚴重嘅話成個盤 |
| **受影響嘅人** | **香港 1941–1979 年夏天出世嘅人**、中國 1986–1991、台灣 1945–1979 |
| **核實狀態** | 暫定（唔係流派問題，係曆法正確性問題） |

**理由**

呢條係跑文墨天機對照（B12b）嗰陣浮出嚟嘅第七個分歧點。

用戶記得嘅係**牆上個鐘**。1990 年 7 月 8 日中國嘅鐘寫住 12:00 嗰陣，
真正嘅標準時係 11:00 —— 中間差咗個夏令時。如果唔還原，真太陽時校正就會
由一個錯咗成個鐘嘅起點開始算，而一個鐘啱啱好係**半個時辰**：
跨到邊就跨，唔跨就冇事。跨咗嘅話命宮成個唔同，全盤唔同。

我哋已經做真太陽時校正（下面嗰節）。夏令時同佢係同一件事嘅兩半 ——
一個係「呢個鐘同太陽差幾遠」，一個係「呢個鐘有冇被人撥快咗一個鐘」。
做咗前者唔做後者，等於將一個 60 分鐘嘅系統性偏差留喺度，然後去校正
一個 10 分鐘嘅偏差。

**點解呢條對觀微特別重要**

香港 1941 至 1979 年幾乎年年都行夏令時（夏天 UTC+9）。即係話
**1979 年之前夏天喺香港出世嘅人，全部受影響**。呢批人正正係觀微最可能嘅用戶。

**呢條唔係流派選擇。** 冇一個流派會話「請用一個撥快咗嘅鐘嚟排盤」。
唔處理夏令時係實作偷懶，唔係師承。所以呢度唔提供 RuleOptions 開關。

**不過有個真實風險要記住**：老一輩命理師慣咗**自己手動減一個鐘**先入軟件
（因為佢哋用開嘅軟件唔識處理）。如果用戶已經自己減咗，我哋再減一次就錯。
UI 要處理呢件事 —— 出生時間欄要寫明「請填出世證明書／記憶中嘅鐘錶時間，
唔使自己調校夏令時」，並且喺命書版權頁列出用咗嘅偏移（工單 H2）。

**實作**：`packages/ziwei/src/calendar/timezone.ts` 嘅 `tzOffsetMinutes()`，
行 `Intl.DateTimeFormat` 嘅 IANA 資料。呢個係引擎入面唯一一個唔純嘅位
（要睇系統時區資料庫），所以 `tablesChecksum` 覆蓋唔到佢 ——
IANA 資料庫更新理論上可以改變舊盤。歷史夏令時記錄好少改，但唔係零。

**對照結果**：文墨天機唔認夏令時，見 `docs/engine-divergence.md` D-002。

## 真太陽時

`trueSolarTime: true`（預設開）。

經度校正 = (出生地經度 − 時區標準經線) × 4 分鐘，另加均時差。

呢個唔係流派分歧，係曆法正確性問題：香港（114°E，用 +08:00）同倫敦
（0°，用 +00:00/+01:00）嘅偏差方向同大細完全唔同，唔校正係**系統性**錯誤，
唔係偶然錯。

校正過就要喺命書版權頁寫明用咗乜（工單 H2）。

## 流派設定（工單 B13）

上面七條規則，加上四化表、廟旺表、萬年曆 checksum 同 `ENGINE_VERSION`，
綁成一個可以 pin 嘅 **`school_profile_id`**。

```
zhongzhou-v1@4f66c68baf4b17cf
```

程式喺 `packages/ziwei/src/school-profile.ts`，每個 `cast()` 出嚟嘅盤
都會喺 `meta.schoolProfile` 帶住佢。

**點解要有：** 語言規範（`docs/voice-spec.md` §17）要求每個結論物件填得到
`school_profile_id`，而且**唔准用未鎖定嘅 `latest`**。冇呢個 id，
成個推理層（工單 C8）連必要欄位都填唔到。

### 「唔用」同「未做」要分得開

流派設定入面每個功能有三個狀態，**唔准只寫「冇」**：

| 狀態 | 意思 | 例 |
|---|---|---|
| `enabled` | 三合派用，引擎做咗 | 本命盤、大限、生年四化、廟旺、三方四正、空宮借星、**流年、流年四化、大限四化、限流疊宮** |
| `disabled` | **三合派唔用。係選擇，唔係缺陷。** | 自化、飛化、向心／離心 |
| `not-implemented` | 三合派用，但引擎未做。⚠ 係缺口 | 流曜、小限、流月流日 |

自化飛化係四化派（飛星）嘅核心機制，三合派唔行嗰套。
規範 §10 講明「特殊規則只可以喺已登記嘅流派設定啟用」——
所以要**明文寫出嚟話唔用**，唔好留喺度俾人日後當成未做完。

`missingFeatures()` 只會列 `not-implemented` 嗰批。
B15 做完之後淨返流曜、小限、流月流日 —— 三樣都唔喺規範 §16 年度門檻嘅必要路徑上，
所以**年度章嘅引擎前提而家齊晒**。

⚠ 但仲有一個**逐年**嘅前提：未起運嗰幾年（虛歲細過五行局數）冇大限層，
`annual().decadal` 會係 `null`。嗰啲年份照樣唔夠 §16 嘅「大限核心支持」，
推理器要出 `grade: null`，唔准硬寫。
