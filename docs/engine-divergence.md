### D-001b　同一個分歧喺流年層放大咗三倍（工單 B15）

| | |
|---|---|
| **狀態** | 已記錄，預期之內 |
| **範圍** | 120 個盤 × 8 年 = 960 個 (盤 × 年) 入面 204 項，全部係四化 |
| **判定** | **唔係新分歧，係 D-001 嘅直接後果** |

本命盤嗰陣，庚干只有**一個入口**：生年天干。
加咗流年層之後變成**三個**：

| 入口 | 邊度嚟 | 撞到庚嘅機會 |
|---|---|---|
| 生年四化 | 出生年天干 | 每十個人一個 |
| 大限四化 | 大限命宮嘅**本命宮干**（五虎遁） | 每十步大限一步 |
| 流年四化 | 太歲天干 | 每十年一年 |

所以同一個流派選擇，喺年度章度會出現得密好多 ——
960 個 (盤 × 年) 入面 204 項，對比本命層 1,000 個盤得 190 項。

**呢個令 R-003 由「一個要記低嘅選擇」變成「一個要喺命書入面講出嚟嘅選擇」。**
一個人一世人至少會有一兩步大限或者一兩個流年撞正庚干；
如果我哋唔講，佢攞去第二個網站對，就會見到化科唔同而唔知點解。

流年層嘅對照結果（`conformance-iztro-annual.test.ts`）：
流年命宮、流年天干、流年十二宮、大限地支、大限宮干、大限十二宮
**全部逐項一致，零差異**。唯一分歧就係四化，而且全部追返去庚干。

## D-002　歷史夏令時

| | |
|---|---|
| **狀態** | 已記錄，**我哋認為文墨錯** |
| **範圍** | 21 張入面 2 張（B03、B04，1990 年 6–7 月）全盤唔同 |
| **本引擎** | 認夏令時。1990-07-08 12:00 中國 → 標準時 11:00 → 巳時 |
| **文墨天機** | 唔認。當東八區永遠 +8 → 12:00 → 午時 |
| **判定** | **唔跟文墨。** 見 `docs/rules.md` R-007 |

呢個唔係流派分歧，係曆法正確性問題。用戶記得嘅係牆上個鐘；
夏令時期嗰個鐘被人撥快咗一個鐘，而一個鐘啱啱好係**半個時辰**。

受影響範圍比睇落大好多：**香港 1941–1979 年幾乎年年行夏令時**，
中國 1986–1991，台灣 1945–1979。觀微嘅用戶群正正撞正香港嗰段。

**點樣證實佢真係夏令時、唔係斗數分歧**：將同一張盤用固定 `Etc/GMT-8` 再排一次，
B03 同 B04 **全部項目即刻同文墨一致**（命宮、五行局、十二宮干、十二段大限、
所有星曜落宮、所有廟旺）。即係話兩邊嘅斗數規則一模一樣，分歧百分百落喺時區。

所以 `conformance-wenmo.test.ts` 對照嗰陣用 `Etc/GMT-8` —— 唔係承認佢啱，
係為咗將時區呢個變數隔離出去，等其餘 58 項比得到。另外有一條專門測試鎖住
「用 Asia/Shanghai 排一定要同文墨唔同」，防止有人日後靜靜雞拆咗夏令時處理。

## 點樣更新呢份文件

`conformance-iztro.test.ts` 一 fail，代表出現咗未記錄嘅差異。次序係：

1. **先假設係我哋錯。** 睇差異落喺邊一層（宮位？主星？輔星？大限？），
   同對應嘅不變量測試對返。
2. 如果確認唔係 bug 而係流派差異：
   - 喺 `rules.md` 開一條 R-xxx，記低我哋揀邊邊同點解
   - 喺呢度開一條 D-xxx
   - 喺測試嘅 `KNOWN_DIVERGENCES` 加返一項
3. 如果係 bug：修咗佢，**bump `ENGINE_VERSION`**，並且諗下舊盤點算
   （見《排盤引擎 v0.1》第九節 —— 舊盤唔自動重算）。

**唔准喺測試度靜靜雞放寬條件令佢綠返。**
