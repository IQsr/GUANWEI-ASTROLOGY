# 共用成書規格 v1（提案）

日期：2026-10-25。狀態：設計與驗收規格；P0 共用紀錄及保存 adapter 已在本機新成書流程實作，見 [P0 交付與界線](book-authoring-p0-2026-10-25.md)，P1首批廉忌昌科與同祿機權已在本機完成，見 [P1交付](book-authoring-p1-2026-10-25.md)；其餘P1／P2與未映射條件仍待後續。對應[問題矩陣與優先次序](book-authoring-audit-2026-10-25.md)。本規格適用於將來新成書，不重算舊書，不改目前網站、SCHOOL_PROFILE、安星或資料庫。

## 1. 讀者成果

每章應讓讀者明白：本盤最值得留意甚麼、為甚麼、與生活取捨有何關係。已成立的原書分支可以直接講清；未知範圍集中到「據」，避免正文反覆解釋編輯流程。深度來自有來源的區分與關係，不靠加字數、列更多星名或增加肯定口吻。

正文不強制固定兩段、不統一每段開場，不要求每粒已計算星曜都出文。資料不足時保持短而完整，不用一般提醒填篇幅。生活內容採用承接本盤重點的編輯建議，沿用用戶已選的方向，不加故事式生活例子。

## 2. 六層共用資料流

```text
出生輸入＋排盤版本
  → AnalysisContext／Facts（實際位置、可查性、來源版本）
  → RuleDecision（必要條件、支持、牽制、例外與未成立原因）
  → ChapterDecision（本章主語、核心重點、相關跨宮關係）
  → 正文／建議／收結（引用相同decision與focus）
  → 段落引用包＋不可變的新書快照
```

重用既有`condition.ts`、`rule.ts`、`pilot-analysis`、宮位predicate adapter、跨宮facts／bindings及保存層，不另造一套按星數或好壞相減的判讀器。新增的是共同承接合約與缺少的原書條件卡。

## 3. AnalysisContext與事實

每次成書提供：成書年份、出生時間及時區來源、明確出生性別或缺值、流派／排盤／四化／查星目錄版本、語言、年齡適用層、所需本命／大限／流年資料。性別不從姓名、配偶、樣本ID或大限順逆倒推。

每個事實含穩定`factId`、星名、原位宮名／宮支、層次、四化、計算方法與來源狀態。查星須區分：已確認在範圍、已確認不在範圍、未實作、未啟用、缺輸入、重複／衝突紀錄、版本不支持。現有engine狀態可經adapter保留，不能把`not_applicable`一律當否定。

「位置可計算」「安法來源已校勘」「原書意義支持」「本盤前提成立」分成四個軸。初階轉錄未校勘狀態不可因深造有象義而升級；現行廟陷有值，不代表深造原表已核。

### 借星的資料合約

- 星曜、四化與配曜只在原位存一份事實，不因借星增加一份或搬宮。
- 另存`BorrowReference{target, origin, majorFactIds, scope}`；原位資料與借入參照分開。
- 某條原書關係允許借會時，該規則明示可用的關係與必要原位；不能一律當實坐，也不能一律禁止借星有進一步分析。
- 原書指定的同度、對拱、三方、相夾、成對、單見及分入兩宮，均為不同關係；相會不能偷換同宮。
- 某借入命宮幾何不合法時記`out_of_scope`，不為湊60×借星而生造入口。

## 4. 有來源條件卡與RuleDecision

每條卡最少保存：`ruleId`、來源書別／指紋／PDF頁或轉錄段定位、原段及前後文ID、主語、宮位角色、時間層、組合與宮支、必要條件、排除條件、修飾、例外、允許借會方式、疑字／版本待核、明確可說及不可擴大範圍。

必要與充分條件分開；「明斷者再見才曜」不能倒轉成「有才曜所以明斷」。眾吉、煞重、調和、府庫等未有經核定義前，保留未知，不用任意兩粒／三粒門檻替代。

每次核對結果分欄：

| 語意狀態 | 意思 | 成文行為 |
|---|---|---|
| supported | 所需條件與來源前提成立 | 可以形成有界限的個人解讀 |
| not_supported | 已核實有必要前提不符／排除成立 | 不採這支；不自動採其相反結論 |
| unknown_input | 安星、輸入、版本或覆蓋不足 | 保存缺甚麼；不寫「確認冇」 |
| source_pending | 原段、疑字、版本或語意尚未解清 | 保存定位，不形成確定規則 |
| out_of_scope | 不屬此主語、星系、宮位或時間層 | 不套用，也不報成個人缺點 |
| valid_not_written | 有效但因相關性／篇幅不獨立成段 | 分析完整保存，重要牽制不能消失 |

其中`valid_not_written`是呈現狀態，不可覆蓋supported等原判讀狀態。位置事實、已符合要求與未符合要求各保留自己的紀錄；引用面板只呈現它們，不重新計算規則。

## 5. ChapterDecision：全書共用重點

建議最小形狀如下，名稱可隨實作調整，但語意欄位不能省：

```ts
type ChapterDecision = {
  chapter: string;
  subjectRole: string;      // 本人／伴侶關係／平輩／親近後輩／上司等
  layer: 'natal' | 'decade' | 'annual';
  focus: {
    id: string;
    question: string;
    factIds: string[];
    decisionIds: string[];
    qualifiers: string[];
    relationIds: string[];
  }[];
  unresolvedDecisionIds: string[];
  validButUnwrittenDecisionIds: string[];
};
```

`focus`按本章用途與來源相關性選取，不能用星曜命中多寡當人格、富貴或吉凶分數。所有已成立、會改變主旨的牽制必須在決策內保留；可與主旨合寫，不必每條獨立起段。

只有星曜位置而未有可用原書關係時，最多列成事實，不把它包裝成生活結論。無selectedRuleId亦不能直接判「無深度」，因為專用分支、殘段context及其他來源關係可能有內容。

## 7. 正文、建議與收結合約

### 正文

每個實質主張保存`claimId`、`focusIds`、`decisionIds`、角色（盤面事實／書中解讀／編輯演繹）。可先用自然語句講重點，再交代必要的本盤原因與生活意思；不將章節變成原書閱讀工作報告。原書的條件與限制可集中於「據」，但會改變正文意思的否定與例外不可只藏在展開層。

不靠「本盤」起句辨識是否個人段落、不以字數篩主張、不從舊偏向plain摘要補缺、不依出生日期／姓名／測試ID選答案。

### 編輯建議

每項建議引用本章`focusId`及相關decision，說明讀者可觀察或處理哪一個已解釋的取捨。建議不冒充書中原句、不新增命理判斷。少年、未有伴侶等生活情境，與原書分支條件分開；不以年齡通用建議替代本盤分析，也不假定已婚、任職或持有物業。

若同一建議可供不同盤參照，毋須為追求不同而改字；但它必須各自接上本章重點，不能只因宮名相同而貼上。

### 收結

讀取命、官、財、福等已選focus及有來源的relation，不再抽正文第一段或`startsWith('本盤')`作撮要依據。收結應交代幾章放在一起後的取捨，不逐章重講。

引用既有章節可作編輯綜合；若新收結加入新的跨宮命理含義，必須先有相應規則／來源與前提。所有收結主張均能反向找到章節決策，不能因引文超集齊全就視為每句已支持。

## 8. 「據」與完整原文

每個有來源正文段落維持一個「據」。編輯建議沒有書證時，不為湊數偽造引用。十二步沿既定公開無據，內部追查合約同樣有效。

展開順序：本盤適用範圍 → 直接支持該主張的原段 → 規則要求／本盤核對／適用判斷 → 修飾及例外 → 完整相關前後文、出處、疑字。

每個support edge標角色：直接支持、必要前提、牽制／例外、對照分支、方法背景。來源包含書別、指紋、PDF頁序／轉錄定位、段ID及完整原段；必要跨頁續文連同保存。

編輯條件以穩定ID＋主語＋宮位關係＋時間層去重。相同條件由三層傳入，集中顯示一次；不同否定、同度／會照、本人／他人、本命／限年即使近義也不能合併。**不自動用語意相似度刪原文或必要條件**；人工合併須保留舊ID對應。

全文、OCR只存忽略tmp，產品既有引文庫按現有授權範圍保存。索引只收定位與摘要，不另複製原書全文到規劃文件。

## 9. 兩個端到端規格例

### RB：廉貞忌與科文同度的福德

位置：廉貞本命忌、文昌本命科實坐申福德。來源：PDF573.b011／b015、574.b001–002。先核「科文」對象集合、同度及本宮主星前提，建立共享卡；不只憑字詞「科」就算完整符合。

成文目標：忙碌所得的樂趣、藝術感受與精神享受、仍不易隨遇而安的修飾可以一起解釋。建議承接投入與滿足的取捨，不把它寫成職業藝術家、健康結論或已發生的生活事實。

驗收反例：把文昌移到對宮／三方、移走廉貞忌、改成借入或缺安星，結果各按前提處理，不能只換一個星名而保留肯定句。原文多譏評與不能隨遇而安的修飾不能因正面藝術段被刪。

### RC：天同祿與官祿天機權

位置：天同卯酉實坐命宮化祿、官祿天機化權。來源：PDF116.b011，連讀116.b003–012及117頁原局／運限分支。此配合的策動支持可講清，毋須仍只介紹空虛／充實比較。

驗收反例：本命天同權所帶的巨門忌屬116.b012另一支；太陰化忌、福德太陽的其他前提及117頁經行句不混用。星名出現或生日相同都不是條件卡的替代。

兩例用來驗證共用流程，實作後必須作用於所有相同完整條件的盤，不得建立RB／RC專用例外。

## 10. 驗收矩陣與完成定義

### 結構及狀態硬檢查

1. 120實坐命宮、24合法借入命宮、全十二宮輸出完整；不存在的借入幾何記不適用。
2. 已核每卡有正例、必要條件缺失、排除成立、資料未知、原位／借入、同度／會照等相關反例；不要求無關維度湊測例。
3. 分析保留全部有效支持與牽制；未成文有原因。新增三條以上同時成立的卡時驗證篇幅選擇不吞掉重要修飾。
4. 正文每個實質主張可追fact／decision／source；建議與收結可追focus。所有有來源段一個據，引用ID可解出，必要原文與例外完整。
5. 角色、少年語境、本命／大限／流年分清；初階／深造來源分開；同一事實與原位不重複計入。
6. 新書生成、公開樣本、預覽使用相同決策；保存後只讀快照，禁止閱讀時重算或覆寫舊書。

### 閱讀與付費價值驗收

先過硬檢查，再用固定八本、24新盤及另行封存未讀盤作盲讀。按清楚程度、本盤差別、生活解釋、建議承接、跨章收束分開記具體例證；同一rubric比較前後，不要求每輪分數上升。

不把詞句重複率、命中規則數、原文字數或主觀付款分數當轉換率。讀者是否願意付款，之後要另外觀察實際試讀／購買行為，不在本規格憑空承諾。

### 完成批次的最小交付

- 一份共同決策合約與現有層adapter，沒有新增平行判讀器。
- 一組有原頁核讀的條件卡及正反例，對全體同條件盤生效。
- 正文、建議、收結及引用同時由這些決策生成或選取。
- 既有樣本／幾何／負例核對通過；原書疑點與未覆蓋範圍明列。
- 雜湊與快照差異逐項解釋；沒有用刷新快照、指紋或固定樣本特判代替核對。

## 11. 保存、版本與語言

未來新決策需保存使用的規則／來源／查星／寫作版本與實際輸入依賴，跟正文及引用一同封存。沿`docs/rules.md` R008–010：舊書不重算，升級只能另造新書；是否需要schema／RPC改動要依最小可用快照另提方案，本規格不預先更改權限或資料庫。

繁簡共享同一決策，分行標籤與引用角色均須覆核。英日目前保存原版快照，不能宣稱已等同中文新解讀；下一階段新譯須沿同一決策逐句核對，未核前不自動猜譯、不靜默改舊書。

本版只定義共同成書與驗收合約；每條新條件卡仍需獨立來源核讀。
