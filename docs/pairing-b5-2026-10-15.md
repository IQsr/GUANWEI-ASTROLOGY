# 兩人對照：《深造講義》夫妻宮章做唔做到依據？（2026-10-15）

> 問：網上嘅紫微合盤冇古籍出處。可唔可以用王亭之《中州派紫微斗數深造講義》夫妻宮章（下篇 宮垣論，PDF p.377–410）做「兩人對照」嘅依據？
> 方法：用本機 OCR 全文（`%LOCALAPPDATA%/guanwei/b5/`）搜全書，再逐頁睇 p.377–404。頁 = PDF 頁。
> 書有版權：呢度只記規則同頁數，冇抄原文段落。

## 結論

**可以做，但只可以做「並排擺」，唔可以做「配對」。**

- 全書**冇**合盤或者合婚嘅方法。「合婚」「合盤」「兩盤」「對方命」「配偶的命」呢幾個詞全書零次。「對方」「雙方」淨係出現過 6 次，全部係單盤斷語入面嘅字眼（p.227、276、386、403、504）。王亭之由頭到尾都係**淨係睇一個人嘅盤**。
- 不過，夫妻宮章大部份條文其實係描述**配偶係點樣嘅人**，例如性格、才能、相處模式。所以有一條守得住出處嘅橋：
  - **甲方**：書話你個夫妻宮會遇到咩樣嘅伴侶（夫妻宮章，已經入咗 `branch/fuqi/`）。
  - **乙方**：書話佢個命宮係咩性格（六十星系，已經入咗 `branch/xingxi/`）。
  - 兩邊各自引返原本嘅頁數並排擺，由讀者自己睇。**星敘唔講「啱」定「唔啱」**，因為書冇呢條規則。
- 冇新規則要作，兩邊嘅內容都已經寫好、而且有出處。要新寫嘅只係頁面框架同私隱流程。
- ⚠ 試砌後要修正：單靠深造伴侶句，有 42% 嘅盤會空。所以骨幹要改用每張盤都有嘅「在感情裡的你」，伴侶句改為有就加。見「試砌結果」。

## 年齡差距要小心

呢類係唯一一處，有兩個人嘅生日就**真係計到出嚟**（書話「相差較大合得來」，再加上佢哋實際差幾多歲）。但係：

- 將兩樣擺埋一齊，就變成判斷「啱唔啱」，即係上次決定唔做嘅「配唔配」。
- 書嘅原意係**趨避**（例如 p.391、p.389：年紀相差大啲就容易適應），唔係話相差細就唔得。

建議：兩人頁**唔計年齡差**。年齡呢條繼續留喺甲方自己本書入面就算。

### 建議頁面：分三層，句少都唔會穿

1. **骨幹（每張盤都有）**：左邊放甲「在感情裡的你」（結論句加留意句），右邊放乙「對方是怎樣的人」（命宮骨架）。兩個人各自嘅樣並排擺，唔需要任何配對規則。
2. **有就加（58% 嘅盤有）**：「書中講你容易遇到的伴侶」同「相處提醒」，用深造嘅伴侶句同相處句，每句帶頁數。
3. **冇就直講**：例如「《深造講義》對你夫妻宮這組星，沒有描述伴侶的類型。」寫一行，**唔好用其他嘢填**。成頁「每句有出處」嘅承諾靠呢行守住。

兩個方向都做（甲→乙、乙→甲）。就算兩邊第 2 層都係空（18% 嘅配對），成頁都仲有兩個「在感情裡的你」同兩段命宮骨架，大約 12 段。

### 試砌時發現嘅兩個問題

- **乙欄係第二人稱。** 命宮章寫嘅係「你的命宮在子」「你偏向莽撞」，放喺甲嘅頁面，「你」就指錯人。要做主語轉換（「你」→「對方」或者乙嘅名），或者用「對方的書這樣寫」做引用框。主語轉換唔係純機械操作，要逐段檢查。
- **乙欄唔係每段都啱用。** 「細讀」段講大限（「行到七殺運……虛歲五十六至六十五歲」），「推力」段講盤面證據，兩段都同兩人相處無關。建議乙欄淨係用「骨架」「偏向」「長處」三段。「偏向」包括「莽撞」呢類負面字眼，畀甲睇之前要得到乙同意，所以 consent 流程更加重要。

## AI 連接句試做（2026-10-15）

背景：用家睇過一個競爭對手嘅合盤功能（要登入，用一次免費，之後收費；後面應該係 LLM 即時生成），覺得三層版太悶。純規則寫唔晒兩個人之間嘅無數組合，所以試吓「規則揀事實、LLM 寫連接句」嘅做法。

檔案都喺 `packages/content/tools/pairing/`：
- `packs/NN.json`：事實包，由 `test/pairing.factpack.test.ts` 產生（指令係 `SIM=1 npx vitest run test/pairing.factpack.test.ts`）。每個人有盤面、在感情裡（結論、留意）、命宮偏向／骨架／長處、深造伴侶句同相處句，每條帶 id 同出處。`01` 係阿晴（1996）同子朗（1990），兩個人加埋 15 條；`02`–`05` 係隨機盤，名係虛構。
- `prompt.md` 同 `schema.json`：每句要列出引用嘅 id，句子分「轉述」同「對照」兩種；唔准判斷合唔合、唔准用比喻做標題、唔准用性別刻板印象。
- `sample-output.json`：由我跟住 prompt 寫，**唔係真 API 跑出嚟嘅**。
- `validate.py`：逐句檢查有冇引用、id 存唔存在、轉述句同引用嘅事實有冇共同片段、對照句有冇引齊兩個人、有冇禁字。樣本通過（11 句，引用 12/15 條事實）。整咗一個故意寫錯嘅版本（「陽光遇見烈火」「安全感不足」「白頭到老」），7 個錯全部捉到。

已知漏洞：「對照」句冇做文字比對，所以佢可以夾帶事實包以外嘅內容，只要引齊兩個人嘅事實就過到關。要再加一關，例如用細模型做 judge，逐句問「呢句有冇超出引用事實」，或者上線初期人手抽查。

成本（估算，未實測）：輸入大約 3k token（prompt 加事實包），輸出加思考大約 2–3k token。Claude Opus 5.5（$4／$20 每百萬 token）每次大約 US$0.06–0.07；Sonnet 5.5（$2／$10）大約一半。system prompt 可以做 prompt caching。生成完要存低，同一對人唔好重新生成，咁讀者每次睇到嘅都係同一頁。

## 真 API 試跑：Sonnet 5.5 對 Opus 5.5（2026-10-15）

指令係 `node --env-file=.env run.mjs`，喺 `packages/content/tools/pairing/` 跑。用 5 對盤（`packs/01–05`），兩個模型都用 effort medium 同 structured outputs，結果放喺 `out/<模型>/`、`out/summary.json`。

| | Sonnet 5.5 | Opus 5.5 |
|---|---|---|
| 每對成本 | US$0.016–0.029 | US$0.046–0.066（約 3 倍） |
| 每對時間 | 7–17 秒 | 15–27 秒 |
| 出處檢查（修正後） | 5/5 過 | 5/5 過 |
| 用「他／她」（名字估性別） | 14 處，5 對都有 | 2 處，1 對 |
| 標題 | 多數係將兩條事實用逗號並排 | 多數有一句真正嘅交叉觀察 |

- 第一次跑 Opus 有 2 對唔過，原因係 validator 有漏洞：「書中沒有條文」嗰句同短盤面事實冇四字相同。已經修正，盤面事實改為認星名，或者接受「夫妻宮……沒有」嘅講法。故意寫錯嘅版本照樣捉到 7 個錯。
- 兩個模型都冇作出事實包以外嘅性格，冇用「莽撞」，亦冇講合唔合。
- Opus 嘅交叉觀察比較有意思，例如 02 對：「嘉怡夫妻宮寫『另一方肯讓』，浩然寫『願意遷就』，兩邊都出現讓的一面」；04 對嘅標題：「兩個人書上都寫到沒說出口的話」。Sonnet 嘅「對照」句多數只係講「兩邊唔同」。
- 樣本只有 5 對，結論係方向性，未夠做定論。

### Sonnet 5.5 第二輪（加咗代名詞規則）

prompt 第 7 條改為「唔准用他／她，事實包冇性別，唔好由名字估」，validator 亦會檢查。淨係重跑 Sonnet，5 對共 US$0.09，每對 6–13 秒。第一輪輸出存咗喺 `out/claude-sonnet-5-5-v1/`，成本表係 `out/summary-v1.json`（兩個模型）同 `out/summary-v2.json`（呢輪）。

- **代名詞：17 處跌到 0。** 5 對全部過。Opus 第一輪仲有 2 處。
- **標題冇改善。** 5 個標題仍然係兩條事實用逗號並排，例如「卓琳在感情裡用照顧代替表達，家朗求安穩、願意遷就」。
- 但係**正文嘅對照句有交叉觀察**，同 Opus 標題講嘅係同一樣嘢。例如 04 對：「兩人書上提醒的都是心裡的事沒有講出口」；01 對：「兩邊的留意都落在『做』和『被對方知道』之間」。即係 Sonnet 搵到重點，但冇擺上標題。可能係 prompt 第 5 條（「標題要用事實裡本身的字」）寫得太死。
- 有兩句對照推得遠咗少少，validator 捉唔到。05 對：「兩人在感情裡都是主動付出的一方」，但志明嗰條事實講嘅係「想得多、調整得快」。04 對：「都沒有把感情寫成要靠說出口來維持」。呢類正正係之前講嘅漏洞，要加 judge 一關或者人手抽查。

下一步建議：將第 5 條改為「標題係正文入面最有份量嗰句對照句，kind 一定要係對照」，再用 Sonnet 跑一次（約 US$0.09）。如果標題追得上 Opus，就用 Sonnet，成本係 Opus 嘅三分一。

### Sonnet 5.5 第三輪（標題改為「最有份量嘅對照句」）

prompt 第 5 條改為：先寫正文，再由正文嘅對照句揀最能講清兩人關係嗰句濃縮做標題，唔係將兩條事實並排。validator 加咗檢查：標題 `kind` 一定要係對照。不過第一、二輪嘅標題本身已經標咗對照，所以呢項檢查捉唔到「並排式」標題，仲係要人睇。5 對共 US$0.13（每對 0.016–0.032），比第二輪貴少少，因為諗多咗。第二輪輸出存咗喺 `out/claude-sonnet-5-5-v2/`，呢輪嘅成本表係 `out/summary-v3.json`。

結論：第三輪 Sonnet 有 3 個好標題，Opus 都係 3 個。之前第二輪 Sonnet 一個都冇。**Sonnet 5.5 加呢兩條規則，寫作質素追得上 Opus，成本大約一半。**

新發現嘅問題（validator 捉唔到）：
- 04 對 Sonnet 轉述咗負面嘅偏向標籤：家朗「較易流於虛浮」、卓琳「小事容易三心兩意」。prompt 第 8 條唔准咁做，但 validator 淨係禁「莽撞」一個字。建議喺事實包度直接唔放偏向事實，或者淨係放偏向句入面中性嗰半。

### Sonnet 5.5 第四輪（事實包唔放偏向）

事實包已經唔再放「偏向」，命宮淨係留「骨架」同「長處」。prompt 第 8 條改為：骨架寫出兩種偏向，唔好講呢個人屬邊種，亦唔好轉述負面嗰種。`sample-output.json` 刪咗引偏向嘅一句。5 對共 US$0.13，5 對都過。第三輪輸出存咗喺 `out/claude-sonnet-5-5-v3/`，呢輪成本表係 `out/summary-v4.json`。
