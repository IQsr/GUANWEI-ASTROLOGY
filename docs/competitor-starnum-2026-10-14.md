# 競品拆解：starnum.com.tw（2026-10-14）

先睇公開頁面同前端程式碼（robots 禁嘅 `/api/` 冇去掃），之後用一個假生日實測咗一次完整流程（見第 7 節）。

## 一句講晒

一個人（IG 網紅 @mychenan，美業／BWL 經銷商背景）做嘅免費紫微＋生命靈數排盤站：**排盤全部喺瀏覽器用開源 `iztro` 計**，命盤存去 Cloudflare，**深入解讀全部鎖住，要 IG 私訊站長人手解鎖收錢**；流量靠近 6,000 篇 SEO 文章，副收入係保健品經銷導購。

## 1. 用戶流程

1. **首頁表單**（`/`）：西曆年月日、性別必填；時辰選填——**唔填時辰就只計生命靈數**，填咗先排紫微。另有出生地（台灣 22 縣市，用嚟做真太陽時）、婚姻狀態、子女狀況（話「有助精準解讀夫妻宮／子女宮」）。年份限 1930 至今。
2. 撳「開始排盤」→ 先 lazy-load `lunar-javascript@1.6.4` + `iztro@2.5.8`（jsDelivr，有 SRI，失敗就退返自己 `/lib/`）+ `index-calc.min.js`，**喺瀏覽器計好成個盤**，塞入 `sessionStorage.CHART_DATA`。
3. 跳 `confirm.html`：生成命盤編號 `ZW-XXXXXX-XXXX`（`crypto.getRandomValues`），`POST /api/charts` 存去伺服器，同時發一個 access token 存喺 `localStorage`。頁面分兩步：①免費睇靈數 ②「傳送命盤編號給 @mychenan」解鎖紫微解讀。有「資料有誤？刪除此命盤」。
4. `chart.html?id=…#access=token`：`GET /api/charts/:id`（header 帶 `X-Chart-Access-Token`），再按 tier 渲染。首頁亦有「查詢已儲存命盤」輸入編號。

## 2. 收費模式：三級鎖 + IG 私訊成交

`chart.html` 入面 `applyLockLevel(basic, advanced)` 分 **免費 / 普通 / 高級** 三級，狀態存喺命盤紀錄（`record.data.basic / advanced`），即係站長收錢後喺後台改旗。

| 區塊 | 狀態 |
|---|---|
| 命盤總覽、十年大運、靈數命盤、九宮格、三大週期 | 免費 |
| 天生命格（四化）、性格、今年運勢 | 免費顯示結構，**白話解讀鎖** |
| 命格亮點、愛情婚姻、財富、事業、置產、職場關係、領導、外地移居、貴人、每月運勢、身心健康、內心世界、風險預警、紫微×靈數 | 全鎖 |

- 每個鎖都係模糊佔位文字 +「私訊 @mychenan 解鎖」按鈕連去 Instagram。**冇公開價錢、冇線上付款**，成交喺 DM 度做，順手推「副業定位／IG 個人品牌諮詢」。
- 保存期：免費 6 個月、普通 1 年、高級終身（私隱政策寫明）——保存期本身就係升級誘因。
- 有 3 個「廣告位」註解，首頁同結果頁放 BWL「百益菌」經銷導購連結（關於頁有披露）。
- 留意：解讀渲染（`renderBhSections`）同 34 萬字元嘅 inline script 都喺前端，鎖係前端判斷 tier 再決定畫唔畫——即係內容好大機會一齊送咗落瀏覽器。我冇去驗證或者繞過，但呢個係我哋唔好學嘅地方：**付費內容要喺伺服器先出**。

## 3. 技術棧

- **靜態站 + Cloudflare 全家桶**：Pages/Workers 前面、R2 存命盤主資料、D1 做索引同狀態、KV 做修復備份；Supabase 係「預設關閉嘅舊事故備援」（佢私隱頁自己講）。
- 冇框架，手寫 vanilla JS，`.min.js?v=日期` 做 cache-busting，靜態資源 `immutable` 一年。`sw.js` 只係一個自我註銷嘅 service worker（之前搞過 PWA 快取出事）。
- 排盤引擎：**`iztro` 2.5.8**（SylarLong 開源紫微庫）＋ `lunar-javascript`；自己寫咗真太陽時校正（`apparent_solar_time_v1`），每個語言有預設出生地經度／時區。四化表係常見嘅「庚：陽武陰同」版本。
- 分析：GA4、Microsoft Clarity（錄屏熱圖）、Cloudflare Web Analytics，加自建 `cdn2.starnum.com.tw/api/perf` 用 `sendBeacon` 打 `chart_viewed` 等事件。
- 前端限流：`_snRateCheck` 用 localStorage 記時間戳（純前端，擋唔到人）。
- 簡繁：首頁一個硬編碼嘅細 `SIMP_TO_TRAD` 字表；文章 zh-CN 係另一套。

## 4. SEO / 內容策略（佢最強嘅地方）

- 關於頁話 **7,975 篇原創文章**；`llms.txt` 寫 zh-TW 5,885 + zh-CN 5,835 篇。主題 hub：紫微基礎、星曜、十二宮、四化、大限、靈數、配對，同埋「事業／感情／財富／健康 × 紫微＋靈數」融合題。
- 標題同 meta 塞滿關鍵字：「免費紫微斗數排盤」「免費生命靈數」「四化大限流年」。
- **AI 搜尋優化做得好盡**：`llms.txt`、`llms-full.txt`、`sitemap-ai.xml`、`knowledge.json`（schema.org）、`/okf/` Open Knowledge Format、`/api/methodology-v2.json`；robots 對 GPTBot／ClaudeBot 等寫 `Content-Signal: ai-train=no, search=yes, ai-input=yes`——唔俾訓練，但歡迎 AI 搜尋引用。
- og:locale 列咗 10 種語言（en/ja/ko/ms/th/id/es/vi），但實際文章只有繁簡兩種。
- 一大堆「治理」頁：負責任 AI、AI 安全、系統卡、資料治理、透明度報告、倫理、無障礙、安全政策……主要係做 E-E-A-T 信任訊號。
- `/karma`「懺悔」頁：心理自助式內容（三分鐘自省、功過格），寫得幾克制，有提醒搵專業協助——係首頁「明明很努力，卻一直不順？」嘅情緒入口。

## 6. 對星敘嘅啟示

**可以學：**
1. **免費盤要即刻有嘢睇**——佢唔使登入、唔使付錢就出完整命盤結構＋大限＋靈數，鎖嘅只係「白話解讀」。同我哋 anonymous-first 方向一致。
2. **時辰選填嘅降級路徑**：冇時辰都有嘢俾（佢用靈數頂上）。我哋可以考慮冇時辰時俾個「只用年月日睇得到嘅部分」，或者直接接去定時辰功能。
3. **命盤編號 + access token**：唔使帳戶都可以返嚟睇、可以傳俾人解盤。
4. **AI 搜尋發現性**：`llms.txt`、`sitemap-ai.xml`、Content-Signal 呢套成本低，我哋可以照做。
5. **刪除按鈕擺喺確認頁**，加埋私隱頁講清楚係「從前台移除」唔係物理刪除——坦白得幾好。

**唔好學／我哋嘅差異點：**
1. **冇引用、冇書**：佢嘅解讀冇講出處；我哋每句可以追到王亭之書／頁（assertive, cited copy）——呢個係最大賣點。
2. **人手 DM 成交**：擴唔到、冇價錢透明度；我哋用 Stripe 一次過買書。
3. **前端鎖**：付費內容唔好送落瀏覽器。
4. **問婚姻狀態、子女狀況**：收多咗敏感資料，而且等於「睇住答案寫盤」，同我哋只講盤上有嘅嘢嘅原則相反。
5. **保健品導購**：傷信任，唔好掂。
6. **引擎係現成 iztro**：佢冇自己嘅派別判斷（例如子時換日、中州派規則）；我哋自家 engine 跟中州派、子時規則有明確選擇，可以喺方法頁講清楚呢個分別。

## 9. 要整嘅嘢（2026-10-14 傾完定落）

方向：**先答讀者想知嘅嘢，再請佢入嚟慢慢睇**。沉浸式命書唔變，只係加入口；唔學佢嘅恐懼文案、冇出處嘅「有助力／需留意」標籤、冷讀文。

1. **「你想知咩」入口**（先做）——命書開頭五六個問題（財運、感情、事業、健康、今年點），撳落跳去相關章節。
2. **標題加讀者講法**（先做）——宮名照留，下面加一行，例如財帛宮 →「點樣賺錢、點樣守錢」。
3. **每章第一句就答**——將結論先行推得更前，一句答案 + 出處，之後先展開。
4. **一頁速覽**——十二宮每宮一句 +「而家行緊邊個大限」，每句連去嗰章。
5. **方法頁**——用庚干化科（中州派天府 vs 通行本太陰，p.291）做例子講流派之分。
6. **刪除**——刪除 token 要跟命盤長期存喺用戶裝置；刪唔到要講清楚，唔好靜靜失敗。
7. **AI 搜尋**——`llms.txt`、`sitemap-ai.xml`、robots Content-Signal。

建議第一步：喺 sample book 做 1 + 2 嘅 mockup 俾用戶睇。
