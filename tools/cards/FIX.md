## 逐張檢查（六類錯處）

1. **漏咗原文前提。** 原文有「且有吉星會合」「見吉化」「無煞」「得祿」呢類條件，就一定要寫入 `when`／`none`。格局名要用原文嘅嚴格定義，例如石中隱玉＝子午巨門＋祿或權＋無煞；唔可以見名就套。
2. **後果配錯條件。** 同一段原文講幾個情況（例如「若化權…；倘化忌…」），每張卡只可以帶自己嗰個情況嘅後果，同埋嗰個情況嘅條件。修完要睇清楚：同星系、同層、同話題嘅卡，有冇可能一齊出而互相打架。
3. **加料或者講強咗。** claim 每一個意思都要喺 `sources` 段落搵得到。
   - 原文冇嘅性格形容（「受人敬重」「腦筋快」「人脈是本錢」）刪走；
   - 原文「尚可」唔好寫成「適合」；「每每」可以寫「往往」，但唔好寫成「一定」；
   - 引用多過一段，就要列晒全部出處。
4. **範圍或者門檻。**
   - 同度（`reach: same`）、三方四正（預設）、夾（`jia`）要跟原文字眼：「同度」「同宮」「坐」係 same；「會」「見」「會照」係三方四正；
   - 「諸曜」係複數；
   - 「見煞忌刑」唔好加門檻寫成三粒煞；
   - 原文點名邊幾粒星，就只列嗰幾粒，例如原文寫魁鉞輔弼，就唔好用 `count: benefic`，因為咁會連昌曲一齊計。
5. **改用新原子。**
   - 用廟旺頂替地支嘅，改做 `{star, at}`。只有原文本身講入廟／落陷，先保留廟旺條件；
   - 原文有「刑」嘅，加天刑；
   - 樞紐分順行逆行嘅，用 `decadeOrder`；
   - 「早年」用 `decadeAge`；
   - 流煞入宮用 `flow`；
   - 原文講平衡嘅，用 `pole: "平衡"`；
   - 之前因為缺原子而標 `needs_atom`、而家寫得出嘅卡，改返做 `draft`。
6. **`rare` 要重新校。** 用大樣本計每張卡命中次數：

```bash
cd packages/content && CARD_DRAFT=../../tools/cards/ming/NN.json CARD_SAMPLE=300 CARD_STATS=<你嘅scratchpad>/stats-NN.json npx vitest run test/card.test.ts
```

`stats-NN.json` 入面嘅 `seen` 係每張卡喺 300 張盤 × 100 年入面命中幾多次。

- **0 次**：條件寫錯，或者盤面上根本唔會出現。對返原文：改條件，或者刪卡並喺交回報告講原因。唔可以標 `rare` 了事。
- **好少**：只有喺 100 張盤嘅預設測試入面真係撞唔到，先標 `rare: true`。
- 其餘一律唔標 `rare`。
